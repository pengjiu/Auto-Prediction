## 本轮 review 结论与实施边界

本轮是基于固定提交的最小 P0 开发，不是完整盈利策略交付。首轮 GitHub 连接器能够读取仓库，但创建开发分支及提交设计文件均返回 HTTP 403；当时没有远程分支、提交或 PR 被创建。本地无法解析 GitHub/npm 域名，首轮已连接远程设备均离线，Node 22.16 低于项目要求的 22.19。因此优先交付可核对基线身份的补丁和原生离线单元检查；全仓类型检查、Vitest 集成测试与真实盘口验收必须明确保持待运行。

精修后的三个直接改动：

1. **经济完整性：** 去掉生成和校验两个位置的子集最小化。四份合约最多只有 80 个原始选择，先全保留，不增加支配求解层。仅成本、逐状态支付和全部资源都不劣时才可做经济支配剪枝。
2. **订单预算：** 新增一个纯固定点 BUY 预算函数，校验逐档数量和成本，区分 VWAP、最差档位、提交限价和最大支出。精确候选使用限价而非 VWAP；费用仍沿用现有已准入的聚合费用模型，曲线费用认证封闭边界不放开。档位取整导致已有成本超过单笔上界时直接拒绝，不能用截断或假定撮合次数掩盖。
3. **计划回放：** 对实际生成的 BUY 订单逐档验证限价、数量、来源成本和最大扣款。SELL、未知费用模型、超预算和不一致来源不通过。此处验证的是有限模拟模型的一致性，不能授予协议级原子性或实盘资格。

后续依序为：原仓库集成验收 → 共同变量有限支付矩阵 LP → 全量文本解析接入 → 时间一致盘口和账户级回放 → 独立决策是否值得继续。先不加入新 Agent、微服务、库存概率模型或真实交易。

最重要的新增回归：恰好一个结果成立时，三份 NO 的最低支付为 2；删除生成器剪枝后，验证器也必须接受这个更大组合。平均价 0.50 但最差档位 0.60 的订单，必须以 0.60 或更保守价格构造限价，原 0.50 利润证书不得沿用。

以下原设计的历史检查结果保留为历史证据，不等于本轮原仓库测试通过。运行范围和本轮结果以 `research/payoff-economics/VALIDATION.md` 与机器可读结果为准。

## 结论与证据边界

建议开展一个有明确否决条件的研究项目，不建议据此部署实盘资金。Auto-Prediction 有可复用的精确计算、证据绑定、模拟与资金台账；尚缺完整、统一的交易经济模型。源码存在可复现的机会漏报与执行价格语义问题。这证明改造空间存在，不证明当前市场有可捕获利润。

首轮实际工作为：通过 GitHub 连接器读取固定提交的源码、研究记录和测试相关路径；核查官方费用、订单、结算及头寸文档；以独立实现复现被审查算法的关键逻辑，并运行有限状态 LP 原型。未运行仓库全量测试，未调用生产密钥，未进行真实交易，未取得足以衡量现时日/月利润的连续盘口数据。运行环境无法通过 DNS 访问 GitHub 下载源，因此没有完成本地完整依赖安装。测试文件是隔离逻辑复现，不是原仓库集成测试。

## 一、改变研发决策的代码发现

### F1. 它已有 2–4 合约编译，不是只能配对

`packages/control-plane/src/relation-payoff.ts` 的 `inspectRelationPayoffReadiness` 接受 2–4 份二元合约；3–4 份与条件性关系需要额外前提审核。`compileReadyBody` 枚举每份合约的 NONE/TRUE/FALSE 三种选择。

因此，新增功能应是更完整的优化目标、数量与执行成本，而不是重新搭建已有的小组编译和前提审核。

### F2. 基于集合包含的剪枝不适合最大化净收益

上述编译器先保留最低支付至少 1 的组合，再删除所有包含更小保底组合的较大组合。它不考虑价格，也不考虑较大组合提高了多少最低支付。

反例：A/B/C 恰好一个成立，三份 NO 的买价各为 0.60。任意两份 NO 最低支付 1、成本 1.20；三份 NO 最低支付 2、成本 1.80。三份 NO 被剪枝删除，尽管毛收益下界为 0.20。实验中 LP 找回该组合；假设曲线费率为 0.05、忽略撮合拆分取整等其他费用时，净下界为 0.164。

这是虚构价格的算法反例，不是实际行情。它证明当前局部编译路径有漏报，不能证明整个项目全部路径都漏报，更不能作为原创 Alpha。

改造：同时删除生成器的仅凭子集关系剪枝，以及 `assertResearchRelationPayoff` 中同样拒绝大组合的校验。仅在有严格的成本—支付—资源支配证明时删除候选。小问题先不剪枝，作为金标准。

### F3. 平均成交价不应充当全部成交的限价

`exact-promotion.ts` 把模拟总支出/数量向上取到价格刻度，放入 `CandidateLeg.unitPrice`；`execution/certificate-shadow.ts` 将该字段用于 `OrderIntent.limitPrice`。

反例：50 份 0.40，50 份 0.60，100 份均价 0.50。限价 0.50 只能覆盖前 50 份，不能取得模拟中的 100 份。此处是从盘口成本证明到订单计划的语义缺口，不是已观察到的实盘损失。

改造：分别保存档位成交计划、预计总支出、完整成交所需最差档位价、提交限价、允许最大扣款。经济证明依赖一个明确的费用与扣款上界；提高限价必须同步提高证明中的保守成本，重新交由 verifier 拒绝不再有正下界的候选。没有原子预算保证时，不以当前 VWAP 充当未来执行保证。

### F4. 曲线费用模拟与认证之间有刻意的封闭边界

`execution/exchange-simulator.ts` 支持 `BINARY_PRICE_CURVE_V1`，但将其标记为 `BOOK_PRICE_CURVE_AGGREGATE_LEVELS_REQUIRES_MATCH_CALIBRATION`；`exact-promotion.ts` 明确拒绝这种模型。

这不是应直接删除的错误判断。聚合档位不能自动说明底层撮合笔数及逐笔取整，官方公式与按档位模拟仍需要核对扣款口径。

改造：在同一经济类型中实现费用上下界、实际扣款资产、取整规则与适用版本。只有能得到可核验费用上界的计划才可认证；没有上界则保留研究状态。费用为零的市场也必须核查具体市场参数，不能用类别猜测。

### F5. 协议转换和全量低延迟行情不是已完成能力

`venue-polymarket/src/index.ts` 将 `CONDITIONAL_TOKEN` 标为未实现；流式解码器只处理完整 book 消息。目录类型主要依赖 `clobTokenIds`；审查时官方文档区分 CTF token ID 与 V2 position ID。

改造：按当前协议版本获取原生资产、抵押品、数量精度、费用、事件组完整性和操作能力；不把 condition ID 当作业务 event/group ID。先实现只读转换模拟与回放，暂不接资金操作。无原生连续序号的来源不能用时间戳伪装成完整的连续序号；断线或无法证明状态连续时，等待完整快照后恢复可交易状态。

### F6. 现有真实研究记录还不支持利润预测

仓库保留的 `real-candidate-disposition.v1.json` 是指定历史快照的 `REJECTED_ECONOMICS`，最高可能净下界为零。`PLANS.md` 另有互补成本 0.47+0.56=1.03 的经济性终止案例。它们证明项目能保留负证据，但不是全市场无机会的证据。

## 二、策略范围

首期只研究一个平台内、少量结算机制清楚且有真实可执行深度的合约组。

### S0：协议恒等式与转换基线

包含真实支持的 Split/Merge/Convert 操作、已有头寸和实际盘口。它是强基线与资金循环工具，不将基础 YES/NO 价差扫描包装成新策略。

### S1：共同观测变量上的复制与覆盖套利（优先）

将同一观测对象、来源、时区、截止、取整和结算例外的阈值/区间/集合合约，编译为有限支付单元。对每个支付单元求组合净收益下界，优化 YES/NO 选择、数量、多档费用和共享资金。

对于单一实数观测的 m 个不同边界，常规观测状态可由边界点及开区间划分为至多 2m+1 个单元；简单统一半开区间通常更少。这不是对含独立异常结算的全部情景数的上界。结算例外须另行加入。

标题同源不够。分别由预言机裁决的市场即使描述相近，也不自动获得协议级联动保证。语义关系应明确其外部结算假设，不能升格为无需假设的协议套利。

### S2：已有持仓的最低成本补全与资金回收

使用 S0/S1 同一支付与经济模型，为既有合法头寸寻找最便宜的对冲/转换/变现路径。原始持仓成本、资金时间和残余风险都保留在账户台账中，不把库存当免费资产，也不把提高最低价值等同于新增现金利润。

可选的后续研究是单侧挂单后补全组合，但它是有成交风险的做市策略，必须单独验证；不能偷偷把这一策略纳入严格套利收益。

首期排除：跨平台资金搬运、基于经济相关性的“必然关系”、开放式政治/法律语义推理、未经支持的跨合约原子成交、为了展示复杂度而构造的超长交易链。

## 三、统一数学模型

令 y 为实际操作量，包含买入、仅限已有库存的卖出，以及经过适配器验证的协议转换。I 是现有资产余额，B 是操作矩阵，c(y) 是扣除费用后的净现金变化。每个有效情景 w 对头寸的支付向量为 h(w)。

第一版从空库存开始的快照级建仓目标可写为：

    maximize z
    subject to z <= h(w)^T q - CostUpper(q), for all admitted w
               shared order depth, cash budget, quantity ticks, minimum size
               no unsupported shorts or conversions

这是全部头寸在指定扣款上界内取得后的条件性下界。它不证明多腿下单过程安全。

库存版本在同一个账户起点比较最终总财富：

    terminal wealth(w) = current_cash + c(y) + h(w)^T (I + B y)

已有库存的购买成本通过总账户现金流/初始资本进入损益。风险下界改进、账面损益、已结算应收和已回到账户的现金分别报告。

对于固定盘口档位，价格和费率是已知系数，优先使用 LP；最小下单量、固定操作费用或离散操作确实需要时再用 MILP。浮点优化器只给候选，候选经过数量刻度处理后必须用固定点重新验算。独立向下取整各腿可能破坏套保比例，不能省略复核。

共同变量模型优先显式有限状态；任意布尔关系才使用 SMT/约束生成。超时或未知不能变成收益证明；背景规则必须有合法状态。是否全局最优和是否具有有效收益下界为两种不同结果。

## 四、语义与证明

全量 LLM 输出支付 DSL、原文定位、共享观测身份、特殊结算规则与未确定字段。价格不参与决定哪个语义解释是真实规则。全量解析不意味着全量认证。

关系证据区分协议保证、经审核且带结算前提的合同关系、研究假设。不能把不同证据等级混成一个置信分数。未知解释保留为更多可能情景或直接拒绝认证，不允许为利润删除不利状态。

证明缓存包含规则版本、合约原生 ID、完整事件组身份、支付表达式、适用假设、撤销条件。价格更新可复用支付定理，但不能复用旧盘口成本证书。哈希只保证身份与完整性，不证明被哈希的语义正确。

## 五、执行成本合同

每个候选至少提供：

- 原生资产/抵押品/协议版本和持仓来源；
- 需要的档位及每档数量、预算占用和共享深度身份；
- 原始可观察时间、接收时间、计算完成时间；
- 原始预计成交总额、最差档位、下单限价和最大扣款；
- 曲线费用、撮合取整上界、转换费用及费用证据；
- 全部建仓后的支付下界和证据等级；
- 每种部分成交、拒单、超时状态的暴露和补救策略。

状态机区分 SUBMITTED/ACCEPTED/OPEN/PARTIAL/MATCHED/CONFIRMED/RECONCILE 等实际语义；具体以当前平台协议为准。提交成功不是成交成功；撤单成功不撤销既有成交；超时不是未成交。不得提前释放无法确认的资金。

FOK 是单笔行为，批量提交不意味着组合原子性。对需要独立多腿成交的策略，支付下界与路径净期望分开评价。若所有允许路径最坏收益均要非负，最优方案可能只能是不交易。

## 六、如何验证能否赚钱

### A. 能力和正确性

同源虚构实例验证代码，不当市场证据。原设计检查含 7 组测试及 50 个由共同分布生成的无套利价格实例；它们均通过相应的预期断言。首批开发另有 43 项聚焦测试和 8 项应用工具测试；没有完成原仓库端到端验收。

### B. 机会存在性

采集规则版本与连续盘口。先建立不考虑延迟、采用乐观成本的指定范围收益上界，定位可研究的组；不能将重复快照独立累加成利润。若覆盖充分后该上界仍小于成本，没有理由研究更快 Solver。

### C. 公平比较

比较四条路径：原始框架、修复经济缺陷后的强基线、共同变量 LP/MILP、加入库存补全。都必须共享同一规则、盘口、费用、资金、深度占用及计算预算。分别归因到 bug 修复、输入覆盖、优化算法和执行策略；不能把扩充输入带来的收益归功于新数学。

### D. 执行与资金

对同一历史轨迹注入不同延迟、撤单、拒单和深度撤回；不能将看见盘口直接当作已成交。没有订单级数据时，不声称掌握真实排队位置；影子模拟不能确认自身市场冲击或对手反应。

按账户级现金流回放：包括失败后的清仓亏损、未完成库存、应收款未恢复资金和运营成本。重叠事件/同日冲击按组评价，不当作大量独立成功交易。

### E. 停止条件

- 语义证据不足、费用无上界、盘口不同步：不认证。
- 仅瞬时理想快照赚钱，合理延迟下亏损：停止以 Taker 完整组合为策略假设。
- 新算法不优于修复后的强基线：停止原创求解研发。
- 收益靠返利、未平库存或未来价格预测：重新分类，不叫严格套利。
- 单一事件占据全部正结果，或成本后样本外增量不稳定：不放大资金。
- 实际平台/地区资格未确认：不接实盘。

统计上的样本外正收益不足以证明没有罕见结算风险。置信范围和压力情景应分别报告。

## 七、最小改造映射

## 八、经济约束示意（非收益预测）

若资金为 K、平均占用率为 u、完成一次资金循环后净边际为 e、平均占用 H 天，那么理想月毛贡献近似为 K*u*(30/H)*e；之后还要扣除运营、失败和残余风险成本。这个估算本身假设机会足够多，不能把它当作目标收益。

虚构例：K=10000，u=0.5，e=0.005，H=3，则仅约 250/月，未扣运营和失败损失。它说明薄边际、浅流动性和长占资可以让正确算法不具备商业价值。
